# Skip-Vision

**Skip-Vision: Efficient and Scalable Acceleration of Vision-Language Models via Adaptive Token Skipping** (ICCV 2025)

This repository hosts the official training and evaluation code for Skip-Vision, built on top of [LLaVA](https://github.com/haotian-liu/LLaVA). The core idea is to shrink the visual token sequence *before* it enters the language model, which simultaneously reduces training FLOPs, inference latency, and peak memory.

- Paper: [arXiv:2503.21817](https://arxiv.org/abs/2503.21817)
- Project page: [index.html](index.html) in this repository

## What Skip-Vision Does

A standard multimodal LLM injects hundreds or thousands of visual patch tokens into the LLM. Skip-Vision inserts a lightweight **Chain-of-Sight (CoS) resampler** between the vision tower and the LLM. The resampler runs windowed cross-attention over the CLIP feature map, keeping only the query tokens needed by each window, so the LLM sees a much shorter visual prefix.

Key implementation entry points:

- `llava/model/multimodal_projector/cos.py` - the Chain-of-Sight resampler
- `llava/model/multimodal_projector/cos_configs.py` - token-budget configurations (e.g. `v1_448_q16+64`)
- `llava/model/llava_arch_index_q_tome.py` - the LLaVA architecture used by the released model
- `llava/model/language_model/llava_llama.py` - the LLaMA causal-LM wrapper
- `llava/train/train.py` - training entry point (`llava/train/train_mem.py` wraps it with memory optimizations)

## Installation

Requires Python >= 3.10, PyTorch >= 2.1, and CUDA >= 11.8.

```bash
conda create -n skip-vision python=3.10 -y
conda activate skip-vision
pip install --upgrade pip
pip install -r requirements.txt
```

Notes:

- Install PyTorch that matches your CUDA version from [pytorch.org](https://pytorch.org/get-started/locally/) if the pinned wheel does not match your driver.
- `pcache-fileio` is only needed when training from an internal object-store dataset. Remove it from `requirements.txt` if you train from a local disk.

## Data Preparation

Follow the LLaVA v1.5 data layout under `playground/data/`:

1. Download the LLaVA stage-1 caption data (`blip_laion_cc_sbu_558k.json` plus `images/`).
2. Download the LLaVA v1.5 stage-2 instruction mixture (`llava_v1_5_mix665k.json`) and link each image root into `playground/data/image_folder.json`.
3. For evaluation, download the benchmark annotations listed in `docs/Evaluation.md` into `playground/data/eval/`.

The training scripts accept plain JSON annotations generated by the official LLaVA tooling; no dataset conversion is required.

## Training Recipe

All recipes live in `recipe/` and are parameterized through environment variables. Skip-Vision is evaluated on three backbones in the paper (Table 2), each with its own token budget:

| Setting | Backbone | Resolution | Visual tokens | Retained / skipped | Recipe |
|:---|:---|:---:|:---:|:---:|:---|
| **SV-LLaVA** | CLIP ViT-L/336 + LLaMA3-8B | 336 | 256 | 100 / 156 | `recipe/sft_llava.sh` |
| **SV-LLaVA-HD** | CLIP ViT-L/336 + LLaMA3-8B | 336-672 | 1152 | 576 / 576 | `recipe/sft_llava_hd.sh` |
| **SV-CoS-80** | CoS resampler + Vicuna-7B | 448 | 80 | 272 / 256 | `recipe/sft_cos.sh` |
| **SV-CoS-336** | CoS resampler + Vicuna-7B | 448 | 336 | - | `COS_BUDGET=336 bash recipe/sft_cos.sh` |
| **SV-CoS-1296** | CoS resampler + Vicuna-7B | 448 | 1296 | - | `COS_BUDGET=1296 bash recipe/sft_cos.sh` |

The CoS setting follows a two-stage schedule: pretrain the resampler at 224px on 558K captions, then instruction-tune at 448px with all parameters unfrozen. The LLaVA and LLaVA-HD settings are single-stage SFT on the 665K mixture.

### 1. Stage 1 - Pretrain the Chain-of-Sight projector

Stage 1 freezes the LLM and trains only the projector on 558K image-text pairs for one epoch with lr `1e-3`.

```bash
bash recipe/pretrain.sh
```

### 2. Stage 2 - Instruction tuning with a 448px backbone

The generic recipe below exposes every knob; the `sft_cos.sh` wrapper above is the recommended entry point for the paper's CoS configurations.

```bash
# 448px backbone -> 336 tokens
bash recipe/finetune.sh

# 448px backbone -> 80 tokens (paper setting)
export COS_CONFIG_VERSION=v1_448_q16+64
export OUTPUT_DIR=checkpoints/sft/skip-vision-7b-448-q80
bash recipe/finetune.sh
```

Useful knobs:

- `COS_CONFIG_VERSION` - resampler config from `cos_configs.py`
- `BACKBONE_RESOLUTION` - input resolution fed to the CLIP tower (`448`, `336`, or `224`)
- `COS_HIGHRES_EXTENSION` - how to expand a 224px-trained projector to a higher-resolution backbone (e.g. `res224to448_80to336`)
- `OUTPUT_DIR` - checkpoint directory
- `PER_DEVICE_BATCH_SIZE` / `GRADIENT_ACCUMULATION` - global batch is `batch * accumulation * world_size`

### 3. Evaluation

```bash
bash recipe/eval.sh \
  checkpoints/sft/skip-vision-7b-448-q336 \
  v1_448_q16+64+256 \
  448 \
  ./playground/data/eval
```

The helper runs POPE and MME and writes predictions and scores under the eval root. Benchmark-specific commands are documented in `docs/Evaluation.md`.

## Repository Layout

```text
llava/               Model code, training loop, and evaluation utilities
  model/             LLaVA architecture variants and the Chain-of-Sight projector
  train/             DeepSpeed-compatible training entry points
  eval/              Benchmark prediction and scoring scripts
recipe/              Clean, parameterized training and evaluation recipes
scripts/             Utilities for dataset conversion and DeepSpeed configs
docs/                Extended documentation (data, evaluation, LoRA, custom data)
playground/          Local data root; expected by the recipes but not committed
checkpoints/         Local output root; generated at runtime and never committed
```
